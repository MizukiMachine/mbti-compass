# 「もう一人の自分」とだけ話すAIは危険 — MBTIシャドウ機能で補完的視点を実装した話

## はじめに

占いアプリ「AnotherMe AI」では、ユーザーのMBTIタイプと同じ性格のAIキャラクターと会話できる機能を開発している。

「自分と同じタイプのAI」と話す。鏡を見るような心地よさがある一方で、**ナルシシズムの強化**と**エコーチェンバー効果**というリスクを抱えていることに気づいた。

この記事では、そのリスクをどう検知し、どうアーキテクチャで解決したかを書く。

---

## 問題：「鏡」モデルの罠

当初の設計はシンプルだった。

> ユーザーがENFP → ENFPのAIキャラクターと話す

同じ感性、同じ価値観、同じ思考パターン。共感は深い。でも、それだけだと**自分の考えが肯定され続ける空間**になる。

特に日本のユーザーでは、欧米に比べて「類似性-魅力効果」（似た人を好む傾向）が弱いという研究結果もある。つまり「同じタイプ」という安心感だけでなく、**違う視点**も自然に取り入れたいニーズがある。

---

## 解決策：Jungのシャドウ機能によるハイブリッド設計

### Jungの認知機能スタックとは

MBTIの各タイプには、4つの認知機能が階層的に並ぶ「スタック」がある。

例：ENFPの場合
- 主機能：Ne（外向的直感）— 可能性を広げる
- 補助機能：Fi（内向的感情）— 自分の価値観に従う
- 第三機能：Te（外向的思考）— 効率的に整理する
- 劣等機能：Si（内向的感覚）— 過去の経験から学ぶ

### シャドウ機能とは

Jung心理学では、意識的な機能の「裏側」に**シャドウ機能**が存在する。Beebeの8機能モデルでは、ENFPのシャドウスタックはこうなる：

```
意識:  Ne - Fi - Te - Si
影:    Ni - Fe - Ti - Se
```

- **Ni**（内向的直感）：一つに絞る深い洞察
- **Fe**（外向的感情）：周りの空気を読む
- **Ti**（内向的思考）：論理的に分析する
- **Se**（外向的感覚）：今この瞬間の五感

ENFPが普段「広げる」のに対して、シャドウは「絞る」「分析する」「現場感覚」と、**補完的な視点**を持っている。

### 設計のポイント

このシャドウ機能を、AIキャラクターの「もう一つの面」として織り込んだ。

- **基本層**：ユーザーと同じMBTI特性 → 安心感・共感
- **成長層**：シャドウ機能の視点 → 補完的な気づき

説教にならないよう、「もう一つの視点からも気づきを提供する」という指示にとどめ、ユーザー自身に気づきを促す形にしている。

## 振り返りプロンプト：エコーチェンバーの防止機構

シャドウ機能に加えて、会話が一定数を重ねたタイミングで**自己振り返り質問**を自然に注入する仕組みを作った。

### トリガー条件

```
会話履歴 >= 16メッセージ（8往復）かつ 8の倍数ごと
```

### 振り返り質問の例（ENFPの場合）

- 「今、いろんな可能性を考えているけど、一番大切にしたいことは何かな？」
- 「過去に似た経験はなかったかな？その時どうだったか振り返ってみよう」
- 「直感だけでなく、論理的にも考えてみるとどうなるかな？」

ユーザーが感情的な話をしている最中は避けるよう指示している。

## 実装のアーキテクチャ

### ファイル構成

```
app/
├── src/data/mbti-characters.ts    ← 16タイプのキャラクター定義
├── src/services/conversation-engine.ts  ← クライアント側会話エンジン
├── app/api/chat/route.ts          ← OpenAI APIプロキシ（サーバー側）
└── app/chat/page.tsx              ← チャットUI
```

### データ定義（mbti-characters.ts）

各キャラクターは以下の情報を持つ：

```typescript
interface MBTICharacter {
  type: string;           // "ENFP"
  name: string;           // "エネ"
  japaneseName: string;   // "活動家"
  emoji: string;          // "✨"

  traits: string[];       // 基本性格
  conversationStyle: {    // 会話スタイル（定量的）
    formality: number;
    emotionality: number;
    logicFocus: number;
    empathy: number;
  };
  empathyPattern: {       // 共感パターン（定性的）
    encouragementStyle: string;
    adviceStyle: string;
    supportStyle: string;
  };
  shadowFunction: {       // シャドウ機能
    name: string;
    description: string;
    complementaryTraits: string[];
    growthPerspective: string;
  };
  reflectionPrompts: string[];  // 振り返り質問
}
```

16タイプ全てに、Beebeモデルに基づくシャドウスタックを定義した。

### サーバー側プロンプト生成（route.ts）

**重要な設計判断：システムプロンプトはサーバー側で生成する。**

クライアントからは `characterId`、`historyLength`、`userName` のみを受け取り、サーバー側でキャラクターデータからプロンプトを構築する。これにより：

- クライアントが任意のシステムプロンプトを注入できない
- APIキーがブラウザに露出しない
- キャラクター設定の変更が即座に全ユーザーに反映される

### プロンプトの工夫

`conversationStyle` の数値はそのままLLMに投げても「感情表現: 90%」と言われても行動は変わらない。そのため、サーバー側で**定性的なテキストに変換**してからプロンプトに埋め込んでいる。

```
formality > 40 → 「丁寧な言葉遣い」
formality <= 40 → 「カジュアルなタメ口」

emotionality > 70 → 「感情を豊かに表現し、温かい言葉をかける」
logicFocus > empathy → 「論理的な分析と客観的な提案を中心に」
```

## レビューで見つかったバグと修正

実装後のレビューで、いくつか重要な問題が見つかった。

### 1. ユーザーメッセージの二重送信（Critical）

**現象**：ユーザーのメッセージがAIに2回連続で送られていた。

**原因**：`chat/page.tsx` で `context.history` に既に `userMessage` を追加しているのに、`callAIService` 内でもう一度 `messages.push(userMessage)` していた。

**修正**：`callAIService` での二重pushを削除。historyに含まれているメッセージをそのまま使う。

### 2. システムプロンプトの外部注入（High）

**現象**：APIエンドポイントがクライアントから `system` パラメータを受け取っていたため、悪意あるユーザーが任意のシステムプロンプトを注入できた。

**修正**：クライアントは `characterId` 等のメタデータのみ送信。システムプロンプトは全てサーバー側で生成。

### 3. setState内での副作用（Medium）

**現象**：Reactの `setMessages` のupdater関数内でAPI呼び出しを実行していた。React 18のStrictModeではupdaterが2回呼ばれる可能性があり、APIが二重発火するリスクがあった。

**修正**：`messagesRef` を導入し、API呼び出しをsetStateの外に移動。refで最新のメッセージ履歴に同期的にアクセスできるようにした。

### 4. 振り返りトリガーが早すぎた（Low）

**現象**：10メッセージ（5往復）で振り返りが始まっていた。ユーザーが会話に慣れる前に介入が入る。

**修正**：`>= 10` → `>= 16`（8往復）に変更。

## 工夫した点と課題

### よかった点

- **シャドウ機能を「説教」ではなく「気づき」として提示**：AIから「あなたはこうすべき」と言うのではなく、「もう一つの視点」として自然に会話に織り込む
- **サーバー側プロンプト生成**：セキュリティと設定管理の両方でメリットがある
- **Reactのrefパターン**：非同期コールバック内で最新の状態にアクセスする必要がある場面で、refによる同期アクセスが有効

### 今後の課題

- **外向きの振り返り質問の追加**：現状の振り返り質問は全て内省型（「自分はどうしたいか？」）。他者の視点を取り入れる質問（「周りの人はどう見ている？」）も混ぜるとエコーチェンバー防止としてさらに効果的
- **Rustバックエンドへの移行**：現在はNext.jsフロントエンドのみ。将来的にはRustバックエンド（`character.rs`, `prompt.rs`）にも同様のロジックを実装する
- **レート制限と認証**：APIエンドポイントにまだ認証とレート制限がない。本番運用前には必須

---

## まとめ

「自分と同じAI」と話す心地よさを残しつつ、ナルシシズム強化のリスクを軽減するため、Jungのシャドウ機能を「もう一つの視点」としてAIキャラクターに組み込んだ。

ミソは2つ：

1. **シャドウ機能 = 補完的な視点の自然な注入**（説教にならない）
2. **振り返りプロンプト = 機械的だが自然なタイミングでの自己内省**

「鏡」ではなく「鏡＋もう一つの窓」。そんなAIとの対話体験を目指している。
